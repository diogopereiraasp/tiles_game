# Azul — jogo de tabuleiro web (HTML/CSS/JS puro, sem build)

Publicado no GitHub Pages (branch `gh-pages`; `main` é a fonte). Para testar localmente use um servidor:
`python3 -m http.server 8000` (abrir o `index.html` por duplo clique não funciona).

## Mapa dos arquivos
`index.html` só tem a estrutura (modais, tabuleiro). Os scripts são clássicos e compartilham o escopo global;
**a ordem das tags `<script>` importa** (config → chat → online-state → account → online → matchmaking → game-setup → bot → turns → ui).

| Arquivo | Conteúdo |
|---|---|
| `css/style.css` | Todos os estilos |
| `js/config.js` | Constantes do jogo (cores, parede, penalidades) |
| `js/chat.js` | Chat da partida online |
| `js/online-state.js` | Variáveis de estado do online (host/convidado) |
| `js/account.js` | Supabase: login convidado/e-mail, perfil, Elo, ranking, `recordMatchResult` |
| `js/online.js` | Relógio de ação, sala via Supabase Realtime (`RtConn`), migração de anfitrião, mensagens host↔convidado, abandono, menus de sala |
| `js/matchmaking.js` | Fila de Partida Ranqueada (`find_ranked_match`), busca e entrada na sala |
| `js/game-setup.js` | Sacola, `initGame`, rodadas |
| `js/bot.js` | IA dos bots (fácil/médio/difícil) |
| `js/turns.js` | Jogadas, pontuação de rodada, bônus finais, `endGame` |
| `js/ui.js` | Renderização, restauração de sessão, `window.onload` |
| `supabase/schema.sql` | Tabelas, RLS e funções (`record_match`, `get_leaderboard`). Rodar no SQL Editor; é idempotente |

## Regras importantes
- **Nunca** colocar no código a `secret key` (`sb_secret_…`) nem a senha do banco do Supabase. Só URL e chave publicável (`sb_publishable_…`). Se a chave publicável for apagada/recriada no painel (Project Settings > API Keys), atualize `SUPABASE_PUBLISHABLE_KEY` em js/account.js: sem isso o jogo inteiro retorna 401.
- **Partida Ranqueada** (fila no servidor) vale Elo cheio. Contra o bot só as 20 primeiras partidas por hora mexem no Elo e acima de 100 resultados/h (bot+amigos) o `record_match` recusa. Sala com código = "amigos": Elo LIMITADO (K=16 pela colocação: 2 jogadores +8/-8; teto 300; no máx. 10 partidas/h com Elo), porque o servidor não conhece o adversário e duas contas combinadas poderiam forjar vitórias; acima de 300 só a ranqueada vale. **Bot também dá Elo, limitado**: rating virtual e TETO por nível (Fácil 50/100, Médio 250/300, Difícil 500/600; K=24, calculado em `record_match`); acima do teto não muda. Sair/reiniciar no meio (>= 4 jogadas) conta como derrota. "Mesmo aparelho" não grava nada.
- Elo é calculado no servidor. O cliente não escreve em `profiles.elo` nem insere em `matches`. Resultado ranqueado: os DOIS jogadores chamam `report_ranked_result`; só vale se os relatos baterem (senão `disputed`). Se um só relatou: saída/tempo esgotado vale na hora quando o adversário está sem sinal de vida há 40s (`ping_ranked_match`, a cada 20s; >= 4 jogadas); fim normal espera 60s (>= 10 jogadas); máx. 5 partidas por par a cada 24h.
- Migração de anfitrião: todos têm o estado completo; se o anfitrião some 10s, o convidado de menor índice presente assume (`hostEpoch` +1). O antigo, ao voltar, vê o `epoch` maior no Presence e vira convidado.
- Testar SQL localmente: Postgres 12 em /Library/PostgreSQL/12/bin com stub de `auth.uid()` e roles `anon`/`authenticated`; o schema roda 2x sem erro.
- Online: o **host** é a autoridade (estado, relógio, derrota por tempo). Mensagens do Realtime não têm ordem garantida — `RtConn.send` numera e o receptor reordena.
- Relógio: SÓ na Partida Ranqueada (`clockEnabled`, viaja no estado): 5 min por jogador = teto, +15 s por jogada confirmada (constantes `CLOCK_*` em js/online.js). Salas de amigos não têm relógio; tolerância de desconexão 5 min (`DISCONNECT_GRACE_PERIOD_MS`).
- `profiles.display_name` é o **nome de usuário**: único sem diferenciar maiúsculas, 3 a 15 letras/números/_, nomes reservados bloqueados (constraint + índice único no banco, `is_username_available` para a tela). Contas novas recebem `jogador########`. Em partidas online o nome do jogador é sempre o usuário (campo travado). Contas não têm e-mail real (`email_norm` fica inofensivo).
- O jogador só tem **nome de usuário** (sem avatar nem foto): vem do perfil (`profiles.display_name`, editado em Minha Conta); o jogo não sobrescreve o nome do perfil.
- Desempate (regra oficial): pontos iguais => mais linhas horizontais completas (`completedRows`); persistindo, vitória dividida (empate no Elo). Os relatos ranqueados incluem `my_rows`/`opp_rows` e o servidor confere.
- Elo começa em 0 (piso 0). Níveis: Bronze <100, Prata ≥100, Ouro ≥300, Platina ≥600, Diamante ≥1000.
- Segurança: nomes/textos da rede são dados, nunca HTML: use `escapeHtml`/`cleanName` (config.js) e `sanitizeIncomingState` (online.js). O anfitrião valida jogadas (`validateGuestAction`: vez, legalidade) e só deixa cada jogador abandonar/renomear a si mesmo; convidados só aceitam mensagens de quem é `host` no Presence. Script do Supabase com SRI e CSP em meta (script-src ainda tem 'unsafe-inline' por causa dos `onclick=` no HTML).
- Sem emojis na UI: use ícones SVG (`ICONS`/`icon('nome')` em config.js; no HTML `<span data-icon="nome"></span>`).
- Plano gratuito do Supabase: poucas mensagens Realtime (~2M/mês). Evite mensagens periódicas frequentes (relógio sincroniza a cada 30s, health check a cada 45s). E-mail embutido é muito limitado: configurar SMTP próprio para o link de "Salvar conta".
- Login: **usuário + senha**, **sem convidado**. Jogar online (ranqueada e amigos) exige conta; bot e "mesmo aparelho" funcionam sem conta. O Supabase exige e-mail, então cada conta usa um endereço interno aleatório `<uuid>@users.azul.invalid` (nada é enviado). Cadastro: `signUp({ email interno, password, options.data.username })`; o trigger `handle_new_user` recusa usuário repetido/inválido/reservado. Login: RPC `login_email_for(usuario)` devolve o e-mail interno. Exige **"Confirm email" desligado**; desligue também "Allow anonymous sign-ins" (o cliente não usa e as funções online rejeitam anônimos via `require_real_user`). Sem e-mail não há recuperação de senha. Se ativar CAPTCHA no Supabase, o cliente precisa enviar `captchaToken` (hoje não envia).
- Ícone do site: `favicon.svg` (azulejo azul com "A"), `favicon-32.png`, `favicon.ico` e `apple-touch-icon.png`, todos referenciados no `<head>` do index.html.
- Chat: mensagem de outro jogador com o chat fechado mostra o alerta grande `#chatAlert` (6 s, toque abre o chat; vibra no celular). Texto sempre via `textContent`.
- Bot (js/bot.js): `botGenerateCandidates` (jogadas legais) → `botChooseMove(idx, engine)` → `botPlayTurn` (executa, com try/catch e modo 'safe' de emergência + vigia `botArmWatchdog`: o bot nunca pode travar na vez dele). Motores do nível Difícil: 'v1' (heurística) e 'v2'/'v3' (antecipam a melhor resposta do oponente via `botSimApply`/`botWithState`); pesos `BOT_LOOKAHEAD_K/W/W3`. **Qualquer mudança no bot deve ser medida**: partidas bot x bot sem DOM (stubs de render/animação/`waitMs`, alternando quem joga primeiro, pontuação final oficial) com >= 800 partidas por configuração (ruído ~±1,5 pt); rode **uma bateria por vez** (duas ao mesmo tempo corrompem o estado global).
- Tema: paleta chumbo (cinza-azulado) definida em variáveis no topo de css/style.css (`--bg-canvas/card/header/recess/hover`, `--border-*`, `--text-*`, `--tile-surface`, usado SÓ nas fábricas: discos e centro); evite cores escuras fixas no CSS, use as variáveis. A peça preta precisa de contraste com `--tile-surface`.
- Efeito 3D das peças: classe `body.fx3d` (CSS no fim de css/style.css), ligado por padrão; botão "3D" só no cabeçalho (`toggleFx3d`, escolha salva em `localStorage['azul_fx3d_v2']`; começa ligado).
- Peças com desenho leve de azulejo (um motivo por cor, na MESMA cor da peça, um tom mais claro e bem discreto): variáveis `--azulejo-<cor>` e `.tile.<cor>::after` no fim de css/style.css. Ligar/desligar: botão pequeno (ícone) no cabeçalho, `toggleMotifs`, classe `body.motifs`, `localStorage['azul_motifs_v1']`, padrão ligado. Os fundos NÃO têm desenho, nem os ladrilhos de referência vazios da parede (só a corzinha de fundo).
- MODO AVANÇADO (lado cinza do tabuleiro): `advancedMode` (config.js). Parede sem cores marcadas; ao pontuar uma linha completa a pessoa escolhe a coluna (a cor não repete na linha nem na coluna): `validCols`, `bestWallCol`, `wallColFor`, `colorPlacedCount`, `wallCellColor` (config.js) e `chooseWallColumn`/`pickWallColumn` (turns.js; o bot escolhe sozinho). Cada jogador tem `wallColors` (cor por casa). Disponível em Treinar vs Bot, Mesmo aparelho e **Jogar com amigos** (checkbox no modal/sala; o modo viaja no estado `advancedMode`); a partida ranqueada usa SEMPRE as regras normais. Online a coluna é decidida pelo anfitrião: o dono da peça envia `WALL_PICK`, o anfitrião valida e confirma com `WALL_CHOICE` para todos (timeout de 60 s => melhor coluna); `receiveWallPick/receiveWallChoice/rearmWallChoicesAsHost` em turns.js. Sem coluna válida ao pontuar: as peças da linha vão ao descarte. Nunca use `WALL_LAYOUT[r].indexOf(cor)` direto: use `validCols`/`wallColFor` (senão quebra o modo avançado).
- Ao testar com duas abas: o jogo salva a sessão em `beforeunload`; zere `isGameActive` e o storage antes de recarregar.
- Publicar = commit em `main` + merge/push em `gh-pages`, só quando o usuário pedir.
- Cache: as tags `<script>`/`<link>` locais em index.html levam `?v=AAAAMMDDHHMM`. **Ao publicar mudanças em js/ ou css/, atualize esse número** (senão celulares ficam com JS antigo e botões novos não respondem).
- Sincronia online: cada jogada (`ACTION`) é numerada por `stateVer` (online-state.js; `sendAction` em online.js; viaja em `getFullGameState`). Convidado ignora número repetido e, se pular, pede `RESYNC` (máx. 1x/3 s; o anfitrião responde com `SYNC_STATE`). O anfitrião rejeita jogada fora de sequência devolvendo o estado. Ao voltar à aba/rede (`onReturnToApp`) o convidado também pede `RESYNC`.
- O descarte reembaralhado em `drawTiles` usa `seededShuffle` (semente: rodada, `stateVer`, tamanho do descarte) no online, senão cada aparelho sortearia fábricas diferentes. **Nunca** use `Math.random()` em lógica de jogo que roda em todos os aparelhos.
- Relato ranqueado: `sendRankedReport` (account.js) tenta de novo em 2/5/10 s e guarda o relato pendente em `sessionStorage['azul_pending_report']` (reenviado ao abrir o jogo; o servidor guarda só o primeiro relato). Fim normal marca `matchFinished`: sair/"jogar novamente" depois disso NÃO é abandono.
- Sessão salva (`saveSessionToStorage`) tem `savedAt`: online > 10 min e offline > 12 h não são restauradas.
- Modo avançado online: o convidado reenvia `WALL_PICK` ao reconectar (`resendPendingWallPick`) caso o anfitrião tenha caído antes de confirmar.
- Quem começa a partida online é sorteado (`randomizeOnlineStarter`); ordem de jogo segue as posições a partir dele.
- Desempenho do 3D: **sem desfoque (blur) em `box-shadow`/`filter`** nas peças e na parede (medido: ~108 ms -> ~16 ms por atualização no celular). Relevo só com linhas nítidas.
- Fluxo de trabalho: desenvolver na branch `dev`; `main`/`gh-pages` só quando o usuário pedir para publicar.
- PWA: `manifest.webmanifest`, `sw.js` (service worker REDE PRIMEIRO: com internet sempre baixa a versão nova; sem internet usa a última cópia; só GET do próprio site e a lib do jsDelivr; Supabase/Realtime nunca passam por ele), ícones `icon-192.png`/`icon-512.png`. Registrado em `registerServiceWorker` (ui.js, só https/localhost). Se mudar a lista de arquivos do "shell" em sw.js, aumente `CACHE`. O navegador embutido do app não suporta service worker (teste de verdade só em Chrome/Safari).
- Testes: `tests/` (ver tests/README.md). Rodar com `node tests/run-all.js`; SQL em `tests/sql/` (precisa de Postgres local com stub de `auth.uid()`).
- Aviso de rede (`showNetNotice`/`hideNetNotice`, #netNotice embaixo), som de "sua vez" com botão (`toggleSound`, `azul_sound_v1`), revanche na sala de amigos (`startRematch`, só anfitrião após fim normal; convidados reabrem ao receber estado com menos jogadas).
- Ranking de Elo paginado: RPC `get_elo_ranking(p_offset, p_limit)` (top 10; quem está logado e ficou abaixo entra no lugar do 10º com a posição real; minha linha é `position: sticky` embaixo da lista). **Todo perfil com conta aparece**, mesmo zerado e sem partidas (as partidas contadas são ranqueada, bot e amigos). Se o servidor não devolver a minha linha, o cliente a monta com o perfil carregado (posição "—"). `schema.sql` termina com `notify pgrst, 'reload schema'` (senão função nova dá "not found in the schema cache"). Se a função ainda não existe no banco, o cliente cai para `get_leaderboard` (sem paginação). "Minhas partidas": 10 por vez (`range`, pede 11 para saber se há mais) com "Carregar mais".
- Sem nenhuma jogada confirmada (`movesPlayed === 0`) não existe derrota por abandono/tempo: `recordMatchResult` ignora e o outro lado vê "Partida cancelada".
- Cache: se o `?v=` de index.html não mudar (mesmo minuto), o navegador reutiliza o CSS/JS antigo; ao testar, use um número novo.
- UI/UX: faixa "Sua vez" (`showTurnBanner`) + vibração (ligadas ao botão de som); avisos do jogo `gameToast`/`gameAlert`/`gameConfirm`/`gameDialog` (config.js) no lugar de alert/confirm/prompt (nunca use os nativos); cabeçalho com menu "Opções" (som, azulejos, 3D) e botões com >= 44 px; brilho sutil `.just-placed` ao confirmar jogada (`placedGlow`, ~0,9 s); resumo de fim de partida (`buildEndSummaryHtml`: tabela por rodada, gráfico SVG e compartilhar) alimentado por `scoreHistory` (viaja no estado, zera em `initGame`); `@media (prefers-reduced-motion: reduce)` desliga animações. Celular deitado (812x375) rola na vertical (tablet deitado cabe sem rolar).
